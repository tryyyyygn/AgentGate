# 路由模式与密钥策略

> 目标版本：1.9.0
>
> 本文是分配模式与权重模式的实现契约。实现、迁移和测试以本文为准；不改变现有分配模式的默认行为。

## 1. 目标

Agent;Gate 支持两套互斥的网关路由策略：

- **分配模式**：沿用当前的客户端到方案分配关系，以及现有的客户端级故障切换。
- **权重模式**：不读取手动分配关系，按密钥启用状态、模型启用状态和权重为每个请求选择候选密钥。

设置页提供全局路由模式切换。现有安装默认保持分配模式；切换模式不删除或覆盖另一套模式的数据，便于回退。

故障切换的配置入口从状态页移动到密钥页。健康、总耗时和 P95 仍属于状态页的观测信息，不在多个页面重复配置。

## 2. 配置契约

### 2.1 应用设置

应用设置增加：

- `routing.mode`: `assignment` 或 `weighted`，默认 `assignment`。
- `routing.strategy`: `fixed` 或 `adaptive`，默认 `fixed`；仅在 `weighted` 模式下生效。

旧的 `failover.{target}.enabled/profileIds` 保留给分配模式使用。权重模式不读取这组候选列表。

### 2.2 密钥配置

每个方案增加路由配置：

- `routing.enabled`: 是否参与权重模式，默认 `true`。
- `routing.enabledModels`: 允许该方案承接的模型 ID 列表。它是渲染进程看到的公开字段；首次识别到模型时默认全选。
- `routing.weight`: 基础权重，默认 `0`。
- `routing.autoDisableOnFailure`: 达到硬故障阈值后是否自动关闭该方案，默认 `false`。

识别到的模型列表仍然属于端点事实 `endpoint.models`，不能被点击操作覆盖。用户点击模型时只修改公开的 `routing.enabledModels`；持久化层保存其等价的 `routing.disabledModels` 集合。

为避免重新识别模型后覆盖用户选择，保存时使用“禁用集合”的等价语义：新识别到的模型默认启用，曾被用户取消的模型保持关闭；实现可以在公开结构中返回启用列表。

### 2.3 运行时状态

以下内容不写入用户配置：

- 连续失败次数。
- 冷却截止时间。
- 半开探测状态。
- 当前的临时粘性候选。
- 自适应计算出的有效分数。

运行时状态按 `客户端 + 模型 + 方案` 隔离。应用重启后清空熔断状态，由主动探测和实际请求重新建立状态。

## 3. 分配模式

分配模式保持现有行为：

1. 网关按 `gateway.routes[target]` 找到方案。
2. 客户端级故障切换仍按 `settings.failover[target]` 的允许方案运行。
3. 现有的连续失败阈值、候选探测、事务化分配和冷却逻辑不改变。

状态页不再编辑故障切换。为了保持现有按客户端的精度，密钥页的故障切换入口应按客户端显示允许状态，而不是把四个客户端的候选库强行合并为一个全局开关。

## 4. 权重模式

权重模式的候选条件：

- 方案启用 `routing.enabled`。
- 方案声明支持当前客户端目标。
- 当前请求模型在 `routing.enabledModels` 中。
- 当前活动端点实际识别到该模型；未识别模型的方案不作为模型请求候选。
- 方案不处于临时熔断或自动停用状态。

候选排序：

1. 运行中且未熔断的当前粘性候选。
2. 基础权重降序。
3. 相同权重时保持配置顺序，避免无意义抖动。

权重表示优先级，不表示流量比例。正常情况下保持 `客户端 + 模型` 的临时粘性，不能因为每次请求重新计算最高权重而破坏上游缓存。

权重模式需要先读取有界请求体并提取模型，再选择方案。读取失败、请求体超限或没有可用候选时返回明确的 4xx/5xx，不把请求转发到未知模型的密钥。

## 4.1 模型映射

每个方案可以配置 `modelRoutes`：把客户端发来的模型 ID 改写为上游模型 ID，Anthropic 与 OpenAI 协议的请求体都适用，分配模式与权重模式都生效。

- 条目形如 `"claude-sonnet-5": { "model": "k3", "labelOverride": "k3", "supports1m": true }`；`labelOverride` 与 `supports1m` 只用于桌面客户端配置展示，网关改写只读 `model`。
- 网关在转发前缓冲有界请求体（默认 32MB 上限），命中映射才重序列化；未命中、非 JSON 或带 content-encoding 的请求原样转发。
- 权重模式的候选判断先把请求模型经映射翻译成上游模型，再按端点识别模型与启用列表过滤；临时粘性、冷却与自适应评分仍按**传入模型**隔离。
- Claude Code 桌面版被接管时，映射表会生成为 `inferenceModels` 条目（保留客户端原生档位名与显示名），桌面功能分档不丢。
- 动态页同时展示客户端请求模型与实际发往上游的模型（`claude-sonnet-5 → k3`）。

## 5. 故障与熔断

- 连接、TLS、网络错误、响应头超时和 5xx 视为硬故障。
- 429 进入短冷却，不直接永久停用。
- 模型不存在、参数错误等模型级 4xx 只排除当前 `模型 + 方案`，不关闭整个方案。
- 一次硬超时可以让新请求临时跳过该候选；连续三次独立硬故障才触发持久的自动停用选项。
- 当前请求已经发送到上游或已经收到响应后，不盲目重放到其他密钥，避免重复扣费和流式内容重复。
- 冷却结束后只允许一次半开请求；成功恢复，失败延长冷却。

自动停用是可选的用户配置。默认只临时熔断，不修改密钥启用开关。

## 6. 自适应策略

固定权重是默认策略。自适应策略只改变内部排序，不修改用户填写的基础权重。

评分使用同一 `客户端 + 模型 + 方案` 的最近 100 条请求：

1. 成功率、超时率和硬故障优先作为可用性门槛。
2. 首字延迟作为主要体验指标，使用稳定的近期统计，不使用单次请求。
3. 总耗时作为次要指标。
4. P95 用于尾延迟惩罚和状态展示，不单独触发切换。
5. 缓存率不作为切换分数，避免切换造成缓存变冷后再次触发切换。

自适应模式仍遵守粘性、冷却和最小样本数，不能因为短期缓存冷热或单次慢请求来回迁移。

## 7. 界面

### 设置页

- 增加“路由模式”：分配模式 / 权重模式。
- 权重模式下显示“权重策略”：固定 / 自适应。
- 切换模式只保存策略，不清理另一模式的数据。

### 密钥页

- 密钥行首增加启用开关。
- 展开区域显示识别到的模型列表。
- 增加“全选 / 取消全选”按钮；部分选中时点击为全选，全部选中时点击为取消全选。
- 增加基础权重输入。
- 增加故障切换/自动停用配置。
- 分配模式保留分配按钮；权重模式隐藏分配按钮，避免用户误以为两套系统同时生效。

### 状态页

- 移除故障切换编辑对话框。
- 保留渠道健康、总耗时、P95、检测模型和历史样本。

## 8. 迁移与安全

- 旧设置缺少 `routing` 时补默认值 `assignment/fixed`。
- 旧方案缺少路由字段时补 `enabled=true`、空禁用集合、权重 `0`、自动停用关闭；公开模型列表会按已识别模型默认全选。
- 旧 `routes`、客户端故障候选和网关接管状态不删除。
- 渲染进程只接收公开路由配置，不接收密文、明文 API Key 或运行时秘密。
- 模式切换不打断已经开始的请求；新请求使用新模式。
- 配置保存使用主进程 Zod 校验和原子写入。

## 9. 验收标准

- 老配置启动后仍使用分配模式，现有路由和故障切换测试不回归。
- 权重模式只选择启用、兼容目标且启用当前模型的方案。
- 全选/取消全选、密钥启用开关和权重可以持久化，重新启动后状态不丢失。
- 同一客户端和模型在正常情况下保持渠道粘性；缓存冷热不触发切换。
- 硬故障会临时熔断，连续故障按策略切换或停用。
- 分配模式与权重模式可以反复切换，双方配置互不覆盖。
- `pnpm test`、`pnpm build`、`git diff --check` 全部通过。
